# 積算AI 開発ログ

> [!abstract] 概要
> PDF図面を **Claude のビジョンAI** に読み取らせ、**部屋ごとに軽天・ボード工事の数量を自動拾い出し**するWebアプリ。
> 「AIが下拾い → 人が画面で確認・修正 → CSV出力」という流れ。KK Generation「積算AI」と同じ発想を、汎用のClaudeで実現したもの。

## 何ができるか（現状）

- PDF（平面図・仕上表・建具表・天伏図・断面図など）を読み込み、ページを画像化してAIに渡す
- **複数ページをまとめて渡し、相互参照**して拾う（仕上表からボード種別、建具表から開口、断面から壁高さ 等）
- 部屋ごとに拾う項目：
  - 天井下地 ㎡ / 天井ボード（種類別）㎡
  - 壁下地 ㎡ / 壁ボード（種類別・面数）㎡
  - 開口補強 m（ドア=2×高+幅、窓=2×高+2×幅）
- 結果は**画面で全項目編集可能**（AIの下拾いを確認・修正）
- **図面に色分け枠を重ねて、拾い結果と照合**（各室＝同色、📍で図面位置へジャンプ）
- **CSV出力**（室別明細＋種類別合計、Excelで開けるBOM付き）
- APIキー未設定でも**サンプルモード**でUI確認可能

> [!warning] 重要
> これはAIによる「**下拾い**」。精度は図面の状態（縮尺・解像度・記載情報）に依存する。**必ず人が確認・修正**してから使う。

## 技術構成

- フロント：**Vite + React + TypeScript**、`pdfjs-dist`（PDF→画像描画、編集UI、CSV）
- バック：**Express**（`server/index.mjs`）が **APIキーをサーバ側で保持**し Claude へ問い合わせ
- AI：**Claude `claude-opus-4-8`**（`.env` で `claude-sonnet-4-6` に変更可＝速い・安い）
  - ビジョン（図面画像）＋ **structured outputs（zod スキーマで構造化JSON）** ＋ adaptive thinking
  - ストリーミングで取得（`max_tokens` 48000、`effort: medium`）
- APIキーは `.env`（gitignore 済み、ブラウザには出さない）

### 主なファイル
- `server/index.mjs` … APIサーバ（`/api/analyze`, `/api/health`）
- `server/schema.mjs` … 構造化出力スキーマ＋AIへの指示（プロンプト）
- `server/mock.mjs` … キー未設定時のサンプル
- `src/App.tsx` … 画面本体（PDF表示・解析セット・色枠オーバーレイ）
- `src/components/ResultEditor.tsx` … 結果の編集UI＋合計
- `src/pdf.ts` / `src/api.ts` / `src/export.ts` / `src/totals.ts` / `src/colors.ts`

## 使い方

```powershell
cd ~/Desktop/claudecode
git pull origin claude/optimistic-thompson-lFZws
npm install            # 初回のみ
copy .env.example .env # 初回のみ。.env に ANTHROPIC_API_KEY を貼る
npm run dev            # http://localhost:5173
```

1. **PDFを開く** → 関連ページを **「＋解析に追加」**（平面図・仕上表・建具表・天伏図・断面 を5〜8枚）
2. 各ページに種別ラベルを入れる（精度↑）／補足欄に縮尺や壁高さ方針を書く
3. **「解析セットをAIで拾う」**
4. 図面の色枠と結果表で照合 → 確認・修正 → **CSV出力**

## API料金の目安（従量課金）
- `claude-opus-4-8`：約 **15〜30円/ページ**（高精度）
- `claude-sonnet-4-6`：約 **8〜15円/ページ**（コスト重視）
- 枚数・出力量で増減。正確な課金は console.anthropic.com で確認。

## 開発の経緯（時系列）

> [!note] 当初は別アプローチだった
> 最初は「PDFを手動で計測（矩形・壁を描く）して積算する」アプリを作っていたが、1/300の大規模図面では実用性が低く、**AI自動拾いへ全面作り直し**した。

1. **手動拾い版**（旧）：PDFベクター解析＋手描きで天井/壁/ボード/開口を拾う。壁の高さ（スラブ/天井下）の分離、開口控除、ページ跨ぎ保持、色分けなどを実装 → ただし操作が重く実用性に課題
2. **AI自動拾い版へ作り直し**：Claudeビジョン＋構造化出力で図面から部屋別数量を生成。APIキーはサーバ側、未設定時はモック
3. **複数ページ相互参照**：平面図＋仕上表＋建具表＋天伏図＋断面 をまとめて解析
4. **堅牢化**：出力切れ対策（ストリーミング＋max_tokens拡大）、長時間解析のタイムアウト解除、空応答のハンドリング、ページ過多の警告／全消去
5. **高解像度化**：小縮尺の寸法を読めるよう長辺2576pxで送信
6. **図面に色分け照合**：各室の位置(bbox)をAIが返し、図面に色枠を重畳。結果表と同色で対応、📍で位置ジャンプ

## 実図面での所感（テスト：物販店舗 65ページ・1/300）
- ✅ **仕上表からのボード種別読み取りは良好**（GB-R t12.5、ボンデ＋PB、化粧石膏ボード等を正しく抽出）
- ✅ 不明点を正直に warnings に列挙（建具表無し→開口不可、断面無し→壁高不明 等）
- ⚠️ **1/300平面図は内法寸法が読みづらく、面積・延長が0になりがち** → 対策は下記

## 既知の課題 / 次の一手

- [ ] **面積が拾えない（1/300小縮尺）** → ①**面積表/求積図**を解析に含める（最有効）②範囲を拡大して解析（クロップ）機能
- [ ] **色枠の位置精度**：大規模図ではアバウト。枠の手動ドラッグ修正、囲んだ範囲だけ再解析
- [ ] 壁高さは断面図/特記から自動判定（スラブまで/天井下まで）
- [ ] フロア・区画ごとに解析→CSV合算の運用テンプレ
- [ ] Excel(.xlsx)直接出力、内訳明細書様式テンプレ
- [ ] 複数ページ結果の統合・保存（プロジェクト管理）
